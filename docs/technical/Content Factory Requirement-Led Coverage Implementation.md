# Content Factory Requirement-Led Coverage Implementation

**Status:** Proposed implementation on `fix/content-factory-requirement-led-coverage`  
**Governing authority:** `80-company-workflows/Content Factory Foundation and Asset Production Model.md`; `80-company-workflows/Content Factory Requirement-Led Coverage Amendment.md`  
**Decision record:** `decisions/ADR-0023-requirement-led-content-coverage.md`

## Purpose

Record the implementation boundary that prevents Content Factory completeness from being inferred from a fixed number of generated objects or from internal reconciliation against an incomplete semantic seed.

This document is implementation truth. It does not replace the governing workflow authority.

## Failure exposed by the AQA Business review

The Foundation compiler already had strong internal reconciliation:

- coverage had to preserve every governed requirement supplied to the compiler;
- v2 coverage required at least one canonical Course Truth node for every governed `skillsOrKnowledge` item;
- Course Truth had to contain exactly the canonical node IDs established by coverage; and
- provider output could not silently add unsupported nodes or broaden named method sets.

Those controls prove **seed-to-Foundation consistency**.

They do not prove **source-to-seed completeness**.

If the governed semantic seed omits an applicable curriculum or exam requirement, the downstream compiler can still be internally perfect. A fixed node count makes the problem worse if that count becomes an acceptance target: the system can preserve exactly the wrong universe indefinitely.

## New reusable guard

`src/content-factory/requirement-led-coverage.ts` introduces a deterministic source-obligation reconciliation boundary.

Inputs:

- a set of source-led curriculum/exam obligations;
- the governed semantic items that may satisfy those obligations; and
- optional explicit supplemental semantic items.

The guard fails when:

- obligation IDs are duplicated;
- semantic IDs are duplicated;
- an obligation points to a missing semantic item;
- a semantic item exists outside the obligation set without being deliberately marked supplemental; or
- a supplemental declaration references an unknown semantic item.

The returned canonical node IDs are derived from semantic structure. No expected number of obligations or nodes is supplied to the guard.

## What the guard deliberately does not do

The guard does not scrape or infer a curriculum automatically.

A course profile must first establish an evidence-governed obligation ledger or equivalent contract from sources permitted by the source-rights model. The ledger must not be generated by simply reflecting the current semantic seed, because that would prove only self-consistency and recreate the original failure.

The AQA Business profile therefore requires a separate source-led reconciliation step before another Foundation can be claimed curriculum-complete. Known review findings are useful regression cases, but the obligation ledger must cover the entire applicable curriculum and exam scope rather than only the defects already discovered.

## Quota removal

`content/business/aqa-a-level/content.test.ts` no longer treats fixed quantities of formulas, links, flashcards, practice questions, case studies, data drills or exam-technique objects as evidence of complete curriculum coverage.

The test retains:

- official course/paper structure;
- identifier/reference integrity; and
- existing exam-shape assertions that are separately governed implementation facts.

Generated counts may still be recorded elsewhere as telemetry. They are not educational-completeness gates.

## Production integration sequence

The forward Foundation sequence becomes:

```text
exact course/cohort
  → source discovery and rights
  → source-led curriculum/exam obligation ledger
  → requirement-led obligation reconciliation
  → governed semantic seed / structured evidence
  → Foundation coverage
  → Course Truth
  → Exam Truth
  → deterministic assurance
  → fresh-context independent review
  → qualified expert review
```

The requirement-led reconciliation must occur before a candidate can make a strong completeness claim.

## AQA 7132 remediation boundary

This branch establishes the generic control and governance correction. It does not falsely declare the existing AQA 7132 semantic seed complete.

Before the next paid/final AQA 7132 Foundation proof, the course profile must:

1. build the source-led obligation ledger for the exact 2027 cohort;
2. reconcile every applicable curriculum and assessment obligation;
3. expand/correct the semantic seed wherever the source-led ledger exposes omissions or contradictions;
4. run the reusable requirement-led guard before Course Truth generation;
5. compile a fresh Foundation candidate with a new fingerprint; and
6. rerun deterministic, independent and qualified-human assurance.

The obligation/node count is expected to change if that is what complete source coverage requires. No previous count is preserved as a target.

## Test strategy

`requirement-led-coverage.test.ts` proves the generic control by checking:

- complete source-obligation reconciliation passes;
- a missing semantic mapping fails with the exact obligation ID;
- unreconciled semantic content fails; and
- deliberate supplemental semantics are allowed without becoming quota obligations.

Future AQA-profile tests must add source-led ledger regressions for material specification obligations and must fail if any applicable obligation becomes unmapped.

## Documentation impact

The normative change is recorded in `80-company-workflows/Content Factory Requirement-Led Coverage Amendment.md` and ADR-0023.

Historical ADR-0021 and retained proof evidence are not rewritten. Statements such as the historical 82-node count remain evidence of that run, but no longer define forward completeness.
