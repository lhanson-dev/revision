# Content Factory Required Coverage Reconciliation

## Status

Implementation checkpoint 5 of the ADR-0019 candidate-recovery architecture.

The Content Factory remains **paused** after Confirmation Pilot #20. This checkpoint is implementation evidence only. It does not restore Reliability Q1–Q7, authorize live-provider/full-course execution, or restore Q8 eligibility.

## Purpose

Close the remaining manufacturing-boundary gap between candidate recovery and curriculum completeness.

The governing Coverage Map determines what the course must contain. Candidate rejection may discard an attempted artifact, but it may not remove a mandatory requirement from the course. The implementation rule is therefore:

**Reject attempts, not requirements.**

Before an immutable course content pack can be accepted by the production/qualification path, every active Coverage Map requirement must have evidence for every channel that requirement declares mandatory:

- `learnRequired` → an accepted Learning artifact;
- `practiceRequired` → an accepted Practice artifact;
- `examPrepRequired` → an accepted Assessment Item;
- every accepted markable Assessment Item continues to require its accepted Marking Pack under the existing Assessment/Marking factory contract.

Requirements explicitly governed as `deferred` or `not_applicable` remain outside this completeness calculation. No other silent omission state exists.

## Implementation

The production and qualification orchestration paths now use `assessment-and-marking-with-coverage-reconciliation.ts` around the existing candidate-recovery factory.

The wrapper deliberately leaves the proven Assessment Item and Marking Pack recovery mechanics unchanged. Instead, it guards the immutable `course_content_pack` write boundary:

1. the candidate-recovery factory generates/checkpoints accepted Assessment Items and Marking Packs as before;
2. immediately before a `course_content_pack` manifest is written, the guard reads the persisted Coverage Map;
3. Learn/Practice evidence is derived from the manifest artifacts and their persisted work-unit requirement ownership;
4. Exam Prep evidence is derived from accepted Assessment Item `requirementIds`;
5. `required-coverage-reconciliation.ts` compares those accepted artifacts with every active mandatory Coverage Map requirement;
6. if any required channel is absent, the course-pack write is refused;
7. the latest durable accepted candidate/Marking Pack checkpoint is preserved and the job becomes explicitly `blocked` with `required_coverage_reconciliation_failed`;
8. no incomplete manifest is accepted merely because other sibling artifacts succeeded.

The same reconciliation is repeated for an already-validating job with an existing manifest, so a persisted pre-checkpoint manifest cannot bypass the new rule when it re-enters the governed orchestration path.

## Recovery semantics

This gate does not turn an ordinary rejected candidate into a course blocker. Candidate-level rejection/resampling still occurs first and remains bounded under ADR-0019.

A course-level coverage blocker occurs only when the factory reaches assembly with a governed requirement still unrepresented by an accepted required artifact. That is an unrecovered completeness failure, not ordinary candidate scrap.

Accepted siblings are not deleted or regenerated by the reconciliation failure. They remain durable evidence for a later governed resume/remediation path.

## Assurance relationship

`coverage-finalization.ts` and the deterministic `coverage-completeness` assurance check remain the later independent assurance backstop. This checkpoint moves the same no-holes principle earlier into manufacturing so an incomplete course pack cannot be accepted and passed forward merely to fail later assurance.

The later Content Accuracy Assurance Gate is unchanged and remains mandatory. Passing assembly reconciliation does not prove educational accuracy.

## Qualification evidence still required

Checkpoint 5 does not itself requalify the factory. Provider-free requalification must still prove, through the real production topology:

- bad required Assessment candidate → reject → fresh replacement → accepted → coverage complete;
- repeated bad candidates → bounded exhaustion → explicit blocker;
- accepted question → bad Marking Pack → replacement → accepted without regenerating the question;
- a provider omits a mandatory requirement from all accepted Assessment Items → course-pack write refused and course blocked;
- required Learn/Practice evidence cannot silently disappear from an assembled pack;
- successful full-pipeline simulations still reach `expert_review_ready` when all mandatory requirements are genuinely satisfied;
- repeated/restart cases preserve unrelated accepted work.

Only after the reset Q1–Q7 evidence is green may a separate Q8 transition consider restoring live/full-course eligibility.

## Documentation impact

No normative authority change is required. Existing authority already requires complete specification coverage, fail-closed assurance and bounded candidate recovery. This document records how the current implementation now enforces that rule at the course-pack assembly boundary.

Historical Pilot #19/#20 and prior qualification evidence remain unchanged.
