# Issue #704 — skill-level assessment provenance, first production slice

**Scope:** B1 / IA-03 under Founder-approved FI-001 Gate B Ready, merged governance PR #711. **B1a MCQ mapping is live** via PR #712 (production-verified 29 October 2026). **B1b calculation mapping is live** via PR #739 (production-verified 30 October 2026). **B2b calculation recheck integration is a separate governed candidate, not yet merged.** Canonical `/revision/app/` React runtime: `PlannerRuntime` → Course Practice → `FocusedLearningWorkspace` → `createMultipleChoiceEvidence` → `recordLearningEvidence` → Supabase owner-only `learning_evidence` JSONB. No alternate route, new planner, schema migration or provider.

## Gap and bounded correction

Previously `PracticeQuestion.specItemIds/nodeIds` existed only during the session and were lost when objective answers were saved. B1a repaired this for MCQs, not calculations. Published structured bank questions have exact `target_item_ids`/`target_node_ids`; ordinary content-pack MCQs have no fine-grained mapping and remain **unknown at skill level**.

For **authored structured-bank multiple-choice questions only**, Practice now includes immutable per-answer `itemMapping` with `mappingVersion: 1`, `source: 'structured-practice-bank'`, exact targeted specification IDs and Foundation node IDs. The saved **multiple-choice evidence uses the existing schema version 2** whenever that mapping is available; the mapping itself is explicitly versioned as `mappingVersion: 1`. V1/v2 results, scores, progress, self-rated flashcards and other evidence types remain valid. Supabase's existing owner-scoped JSONB and version 1/2 schema-version column contract accept this additive payload without a database migration; duplicate-ID idempotency protections are unchanged.

When the validated objective question has **exactly one target specification item**, the raw answer may be attributed to that one item. A multi-target question carries its target-list provenance but cannot award per-skill credit as a single mark cannot distinguish targets. No mapping, unsupported scope, or a legacy answer never silently becomes a precise skill score. `individualSpecItemObservation` returns the **individual raw result only**, including confidence, source answer, time, module and topic; it is **not** an education claim, mastery diagnosis, progress status or new planner scoring formula. Incorrect/certain and correct/guessed remain different observations. Revision requires repeated/representative and assessment-relevant evidence before claiming understanding.

## Acceptance and limits

Tests cover a real published bank MCQ, two different same-topic specification skills and outcomes, ambiguous multiple-target refusal, untagged course-pack/legacy compatibility, rejection of mappings attached to version 1 evidence, and idempotent JSONB-shaped persistence/reload. The existing isolated Playwright real-GoTrue/PostgREST Plan test is extended to persist a genuine structured-bank v2 answer with versioned item mapping with an ordinary authenticated synthetic user and read that exact item mapping back from owner-scoped Supabase storage; it never connects to production or modifies a real learner. Full exact-head CI and real signed-in Course Practice→Plan adaptation acceptance remain required before merging or claiming useful student value. No child-data account or content is modified during this candidate change.

**Still not implemented:** calculation *method* or partial mark-level skill allocation; per-question authored content fingerprint beyond stable ID; confidence-calibrated durable *skill mastery* model; Psychology plain-pack question tagging; Paper 3 option-specific per-skill denominators; targeted repair/retest (#705); exam workload/shortfall; live learner acceptance. Those remain on #704/#705/#694/#703 and #698. Never claim #704 complete on this first slice or infer all 344 Business specifications have independently verified practice.

**Docs impact:** technical implementation note accompanies code/tests in this PR; approved governance, historical audits, database and legal/public-launch processes remain unchanged. Later code PR(s) will keep this document current, add authentic persistence/skill-state assurance and check the Defect/Assurance register as needed.


## B1b follow-up: published single-number calculation identity (30 October 2026)

**Released via PR #739 on 30 October 2026.** Following production release #734, the existing audit discovered that four independently scored decision-tree Practice calculations appear in the learner supply list but `createCalculationEvidence` did not save the existing bank `itemMapping`. These are automatically marked **final-number answers**, not software-checked workings, drawn trees or business decision quality.

B1b extends the **same** `mappingVersion: 1`, source-tagged `itemMapping` contract to the existing calculation evidence schema v2 without changing evidence row IDs, database, authentication, migration, status labels, score weighting, or planner algorithm. The ordinary `FocusedLearningWorkspace.checkCalculationAnswer` passes the exact source question's mapping through `createCalculationEvidence` to the existing owner-scoped `learning_evidence` JSONB. On subsequent reload, `individualSpecItemObservation` may return the raw observation when and only when the marked calculation has **one** published target: `scoring: software-scored-final-number`. Multi-target calculations retain their linked targets but yield **no** individual-skill observation; untagged questions and older calculation rows without the new field remain broad topic evidence, and cannot be retroactively credited. Question id, confidence and wrong/right outcome retain their original meaning. The score remains a single objectively marked value, not proof of the calculation procedure, confidence, retention or mastery.

Target checks in `src/app/scored-calculation-item-evidence.test.ts` use **all three real published AQA Business paper ContentPacks** and both original expected-value and net-gain cases; verify exact IDs and source targets, wrong-and-certain versus right-and-guessed, multi-target/legacy refusal, and existing idempotent evidence persistence/reload. Existing owner-only database/RLS, signup, responsive browser and production smoke gates remain mandatory; no assurance is waived. The existing GoTrue/PostgREST B1a journey proves the storage contract, while a genuine real-learner calculation result affecting a later plan still requires separate acceptance.

**Deliberately excluded:** representing a right number as validated method, automatically diagnosing a misconception solely from one answer, using partial numerical marks for distinct skills, creating content or an AI marker, changing planning/REV, granting unsupported Psychology item credit, and claiming full #704/#705/#698/#703 completion.

**Documentation impact:** the existing technical B1 implementation note is amended in the same branch as code and tests and INDEX's misleading candidate description is corrected. Existing normative `Claims and Progress Governance`, `Course Learning Blueprint` and `Adaptive Revision Planning` already require exact evidence provenance and unknown-by-default skill conclusions. No new authority or ADR is required. Earlier audit records remain dated evidence and are not rewritten.


## B2b follow-up: final-number evidence to independent existing-asset rechecks (30 October 2026)

**Candidate PR, not yet released.** Under the Founder-approved bounded FI-001 Gate B B2 scope (#705), the existing `src/app/skill-recheck.ts` and shared `preparationCandidatesFromLearningState` now accept the same precisely mapped software-scored **calculation** answers already saved by B1b. Before this change, B1b persisted exact decision-tree skills but the existing repair/recheck finder ignored all calculation evidence. The canonical route remains `/revision/app/` (Courses → Practice, existing FI-001 Plan / Home / REV entry points). There is no new planner, persistence table or formula. Home/Plan's existing focused activity gains a bounded typed-number view for selected calculation rechecks, because the previous focused quick-check renderer accepted only multiple-choice options.

The finder requires the current authored single-target published question, exact matching specification and node mapping, compatible course/module/topic, and a software-scored result still consistent with the current published final-number key. Legacy, ambiguous multi-target, untagged, cross-module, stale/altered-key or unverifiable rows cannot produce a skill-specific recommendation. An incorrect final number or a correct answer marked `guess` can cause a **different, unattempted, published** one-target question for the same assessed specification item to be offered through the existing one-question start pathway. The learner types a number, selects confidence, and receives the authored worked answer only after the response is saved; the same score checker, evidence schema and session-completion retry semantics are retained. Copied prompts and scenarios, even under different question IDs or formats, are not independent. If the published inventory lacks a different eligible question, no phantom recheck is scheduled; known exact Foundation Learn pages can still be offered where the existing workflow permits. A later valid independent result removes the immediate recheck demand but **does not certify mastery or method**.

Tests include focused Home/Plan typed-number launch, saved-result-only reveal, and actual Business 7132 Paper 1/2/3 published packs, separate expected value and net gain faults in the same topic, confidence, wrong-then-right and regression, reload-shaped retained rows, tampered keys/mappings, legacy/multi-target/course isolation, unattempted question availability and one shared Plan candidate. This does not claim a full same-learner signed-in journey, complete #704 or #705, verified method, psychological diagnosis, universal repair or whole-course adequacy. Post-merge production and real learner acceptance still belong to #703.
