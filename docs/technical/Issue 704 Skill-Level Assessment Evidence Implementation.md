# Issue #704 — skill-level assessment provenance, first production slice

**Scope:** B1 / IA-03 under Founder-approved FI-001 Gate B Ready, merged governance PR #711. **Candidate branch, not yet released.** Canonical `/revision/app/` React runtime: `PlannerRuntime` → Course Practice → `FocusedLearningWorkspace` → `createMultipleChoiceEvidence` → `recordLearningEvidence` → Supabase owner-only `learning_evidence` JSONB. No alternate route, new planner, schema migration or provider.

## Gap and bounded correction

Previously `PracticeQuestion.specItemIds/nodeIds` existed only during the session and were lost when objective answers were saved. Published structured bank questions have exact `target_item_ids`/`target_node_ids`; ordinary content-pack MCQs have no fine-grained mapping and remain **unknown at skill level**.

For **authored structured-bank multiple-choice questions only**, Practice now includes immutable per-answer `itemMapping` with `mappingVersion: 1`, `source: 'structured-practice-bank'`, exact targeted specification IDs and Foundation node IDs. The saved **multiple-choice evidence uses the existing schema version 2** whenever that mapping is available; the mapping itself is explicitly versioned as `mappingVersion: 1`. V1/v2 results, scores, progress, self-rated flashcards and other evidence types remain valid. Supabase's existing owner-scoped JSONB and version 1/2 schema-version column contract accept this additive payload without a database migration; duplicate-ID idempotency protections are unchanged.

When the validated objective question has **exactly one target specification item**, the raw answer may be attributed to that one item. A multi-target question carries its target-list provenance but cannot award per-skill credit as a single mark cannot distinguish targets. No mapping, unsupported scope, or a legacy answer never silently becomes a precise skill score. `individualSpecItemObservation` returns the **individual raw result only**, including confidence, source answer, time, module and topic; it is **not** an education claim, mastery diagnosis, progress status or new planner scoring formula. Incorrect/certain and correct/guessed remain different observations. Revision requires repeated/representative and assessment-relevant evidence before claiming understanding.

## Acceptance and limits

Tests cover a real published bank MCQ, two different same-topic specification skills and outcomes, ambiguous multiple-target refusal, untagged course-pack/legacy compatibility, rejection of mappings attached to version 1 evidence, and idempotent JSONB-shaped persistence/reload. The existing isolated Playwright real-GoTrue/PostgREST Plan test is extended to persist a genuine structured-bank v2 answer with versioned item mapping with an ordinary authenticated synthetic user and read that exact item mapping back from owner-scoped Supabase storage; it never connects to production or modifies a real learner. Full exact-head CI and real signed-in Course Practice→Plan adaptation acceptance remain required before merging or claiming useful student value. No child-data account or content is modified during this candidate change.
