## Backend boundary (migration `20261115193000_add_lf05_restricted_written_practice.sql`)

- `lf05_private.lf05_test_memberships` is a new non-exposed, RLS-protected named cohort, empty on installation. The only authorised admin path is a separate accountable controller GO after real risk/release proof. Only a privileged role can create/revoke memberships. The tightly scoped `SECURITY DEFINER` check lives in the dedicated **non-exposed schema** and checks `auth.uid()`, JWT `is_anonymous` and **live** membership expiry each access; never trust user-editable metadata, client-side hiding or stale JWT app flags.
- `public.lf05_written_questions` contains original *question stem and stimulus only*, per-ID course/topic/paper/skill, practice-style marks, fingerprint, training-only classification, approved-source reference and `held|published` state. It is **empty** at migration and only service-controlled/editor-approved original content can be separately published. RLS selects only individually published records for entitled permanent signed-in learners, no authenticated insert/update permissions.
- `public.lf05_written_guides` holds Revision-authored non-examiner guidance **separately** from stems; a distinct RLS policy requires the current entitled learner to have a matching nonexpired, source-fingerprint submitted/completed answer before the guide is readable. It is *not* shipped in public JS bundles or leaked in stems. Empty until a separate item release.
- `public.lf05_written_attempts` is per learner/course/question/attempt, version-controlled, with a **14-day creation-anchored immutable expiry**, 30k-character bound, owner-only RLS with revocable entitlement, and phases `draft → submitted → completed`. The server asserts on submission that a >=100-character **previously confirmed saved draft** is frozen exactly. Its original text is immutable thereafter. Completion scrubs the raw text, keeping only limited submitted provenance. Hourly database deletion removes every expired row. A draft, guidance view and self-mark do **not** generate objective learning evidence. Before real child use, review backups/PITR and processor deletion limitations.
- PostgREST reads and updates require both owner RLS and entitlement. A stale CAS revision, content mismatch, inaccessible draft or lost write acknowledgement produces a visible **not confirmed** result, not a false save. Never create or reuse a pseudo-verified 2027 AO split. The original research draft PR #834 remains unpublished; no credentials, child identities, private answers or real memberships in code.
