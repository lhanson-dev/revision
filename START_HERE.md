# Start Here

Revision is adopting a governed Product Operating System around an existing implementation.

## Current mode

**Light Adoption — migration in progress.**

Until migration is declared complete, existing code, README content and implementation behaviour are evidence of current state. They are not automatically approved organisational authority.

## AI agents — read before working

1. Read `INDEX.md`.
2. Read `MIGRATING_EXISTING_PROJECT.md` while migration is active.
3. Locate the authority governing the task.
4. Distinguish intended authority from current implementation evidence.
5. Do not infer approval from code, research, screenshots, prototypes or prior conversations.
6. Preserve historical evidence.
7. Work on a branch and use a PR for governed changes.
8. **Stop before every merge unless explicit Founder approval has been given for that specific PR.**

## Default merge rule

Every merge into `main` requires explicit Founder approval, regardless of change type. Passing tests, technical mergeability, another review, or Founder authorship does not replace explicit approval.

The Founder may later delegate merge authority only through an explicit Founder-approved governance change.

## Migration sequence

1. Inventory the existing knowledge estate.
2. Establish the constitutional kernel.
3. Identify candidate authority and conflicts.
4. Promote authority deliberately, one domain at a time.
5. Separate implementation truth into `docs/technical/`.
6. Reconcile implementation against approved product/journey authority.
7. Declare migration complete when current authority is clear and legacy sources have dispositions.
